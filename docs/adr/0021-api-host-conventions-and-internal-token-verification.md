# 0021 — API host conventions and internal-token verification

- **Status:** Accepted
- **Date:** 2026-10-19
- **Rules affected:** `.claude/rules/api-contract.md`, `.claude/rules/auth.md`, `.claude/rules/backend.md`
- **Implements:** the API half of [0002](0002-gateway-session-es256-internal-token.md); completes the HTTP mapping [0020](0020-idempotency-scoped-to-a-server-owned-subject.md) left to 1.7

## Context

`Arts6311.Api` had no conventions: a bare `AddControllers()`, one route gated on `IHostEnvironment` because no authentication existed, and a hand-written 500 in place of a `ProblemDetails`. ADR 0002 decided *what* the gateway signs; nothing had decided how the API verifies it, how a failure is shaped, or how the contract is held still.

Every endpoint from 2.x on inherits whatever is decided here, so the cost of getting it wrong compounds. The forces:

- The API must trust exactly one caller and one scheme, and no browser credential (ADR 0001, 0002).
- A new route must be protected by default. "Someone forgot `[Authorize]`" must not be a way to publish data.
- Product routes take `token_use=user`; `/api/v1/internal/**` takes `token_use=service`.
- A stable error `code` plus the correlation id is part of the contract, for the Angular apps and for support.
- The contract must break loudly, in review, not at a client.

## Decision

- **Versioning is literal `api/v1/...` route templates**, enforced by `ApiRouteConventionTests` against the endpoints the host actually built. No `Asp.Versioning`. A second version is a second literal prefix.
- **Secure by default through `MapAuthenticatedControllers`.** It maps controllers and adds the `AuthenticatedUser` policy to every endpoint carrying neither `IAuthorizeData` nor `IAllowAnonymous`. The condition is the decision: authorization requirements *compose*, so a blanket `RequireAuthorization()` would require an internal route to satisfy both `token_use=user` and `token_use=service` at once, which no token can do. A test proves every action is either policy-gated or explicitly anonymous.
- **`token_use` lives inside every policy, *and* in the framework default.** `AuthenticatedUser`, `CmsEditor`, `CmsAdmin` and `Member` all require `token_use=user` (and a `sub`); `InternalService` requires `token_use=service`. A service token with an `Admin` role is therefore refused by every product route. `SetDefaultPolicy` replaces ASP.NET Core's own default, which is "any authenticated user" and which a service token satisfies — without that, a future controller written as a bare `[Authorize]`, or `[Authorize(Roles = "Admin")]` with no policy name, would accept a service token on a product route, because the convention deliberately leaves an endpoint that already declares authorization alone.
- **A user token must name a user.** The user policies require `sub`. Otherwise a `token_use=user` token with no subject authenticates as a nameless principal, and every resource-level rule in Business ("a member reads only their own subscription") has nothing to compare against.
- **The ≤ 2 minute lifetime is validated as a property of the token.** Default lifetime validation only compares `exp` with now, so a signature-valid token claiming an hour would be accepted while young. `OnTokenValidated` additionally rejects `exp - nbf > MaxLifetime`, and rejects a token with no start instant at all (neither `nbf` nor `iat`), because an unbounded lifetime cannot be checked. **The gateway must therefore set `nbf` (or at least `iat`) on every token it signs** — a 1.8 obligation, covered by a test there.
- **ES256 only, with zero clock skew.** `ValidAlgorithms` is `[ES256]`, so an HS256 token or `alg: none` is rejected on its header before any key is consulted. The default five-minute skew would nearly triple a two-minute token's life, so it is zero.
- **The API holds only the public key, and refuses a private one.** `InternalTokenOptions.ImportPublicKey` rejects a PKCS#8 `PRIVATE KEY` PEM and runs at startup: a key problem is a startup failure, never a 401 on every request. The plausible mistake is real — the gateway's generated parameter *is* a private key PEM. The curve is checked **by OID, not by key size**: brainpoolP256r1 and secp256k1 are also 256-bit, and a key on either would pass a size check and then fail every signature verification with no obvious cause.
- **A rejected token never reaches the logs, and that is tested rather than configured.** Our handler logs the exception type only; IdentityModel's own messages quote claim values and sometimes token material. `InternalTokenLoggingTests` captures every category at `Trace` and asserts neither the token nor any of its segments appears, so the guarantee survives someone raising a log level in Azure. A companion test asserts the rejection *is* still recorded, so the guarantee cannot be met by logging nothing.
- **`ProblemDetails` for every failure, with `code` and `correlationId`.** The status is derived from the code in one place (`ApiProblemDetails`), so a code cannot mean 409 on one route and 422 on the next. An unmapped code is a 400: an `OperationError` is an expected failure the caller can act on, and a server fault throws instead. `UseStatusCodePages` and `UseExceptionHandler` give the framework's own empty 401, 403, 404 and 500 a code too, so no failure is unidentifiable. A module's error extensions cannot overwrite `code` or `correlationId`.
- **The OpenAPI document is the compatibility gate.** `AddOpenApi` in Development only; the snapshot at `src/Arts6311.Tests/Api/Snapshots/openapi-v1.json` is compared on every run and regenerated with `UPDATE_OPENAPI_SNAPSHOT=1` in the same change. A document transformer clears `servers`, so the snapshot encodes no host or port and the public base URL stays the gateway's. `OpenApiContractTests` also mutates the document and asserts the comparison rejects it, so a green run cannot mean "the check is asleep".
- **`/api/v1/site/health-info` has no DataLayer or repository.** It returns `status` and the clock's instant, and performs **no I/O** — no persistence, no gateway call. An empty DataLayer and repository added to complete the shape of the seam would be the defect, not the fix. (Not because the result is "deterministic": the instant changes on every call. The reason is the absence of I/O.)

  **The precedent is bounded:** a Business operation may skip the DataLayer *only* when it does no persistence and no provider call. Any database read, even of a single status row, goes through a DataLayer. `IOperationsDataLayer` is still a constructor parameter of `OperationsBusiness`, so nothing structurally prevents a call; the guard is `OperationsHealthInfoTests`, which injects a DataLayer that throws on every method, making it a regression test for this operation rather than a structural proof. It returns nothing about the host, build or environment: it is anonymous and internet-reachable through the gateway, and a version or machine name there is free reconnaissance.
- **Development-only routes do not exist outside Development.** `[DevelopmentOnly]` removes the controller from the MVC controller set, so the route is absent rather than merely refusing. Prompt 1.5's `IHostEnvironment` check inside the action ran *after* authorization, so outside Development an anonymous caller got 401 and an admin got 404 — it contradicted api-contract.md's "404 elsewhere" and confirmed the route's existence to anyone who asked. Removing the controller also lets such a controller inject facades only, retiring 1.5's documented `backend.md` exception.
- **The ping route is excluded from the OpenAPI document** (`[ApiExplorerSettings(IgnoreApi = true)]`). It is scaffolding; publishing it as contract would make its deletion in 1.12 read as a breaking path removal.
- **The document describes the errors every route can return,** through an operation transformer rather than per-action attributes: the failures come from the shared pipeline, not from the controllers, and a per-action variant would drift as routes are added. `ProblemDetails` is a hand-written component so that **`code`, `correlationId` and `errors` appear in the schema** — they live in `ProblemDetails.Extensions`, which a generator can only see as a dictionary, and they are the fields every client branches on. This reverses the consequence an earlier draft of this ADR recorded.
- **JSON only.** MVC's default formatters also advertise `text/plain` (for a bare string) and `text/json` on every response, which lets a generated client type a body as `string`. Both are removed. Removing a media type once a client exists is a narrowing, so it happens now, while there is no client.
- **Times are written with an explicit `+00:00` offset,** which is what `System.Text.Json` does with a zero-offset `DateTimeOffset`. `format: date-time` cannot distinguish that from `Z`, so `HealthInfoEndpointTests` asserts the raw string: the spelling is part of the contract and changing it later would be breaking.
- **Mirrored constants for the gateway.** `InternalTokenDefaults` holds issuer, audience, claim names and the maximum lifetime. The gateway cannot reference the API (`ProjectReferenceTests` pins it to ServiceDefaults only), so 1.8 mirrors them and a test in `Arts6311.Tests`, which references both, asserts the copies agree.

## Options considered

| Option | Cost / trade-off |
|---|---|
| **Literal `api/v1` routes + a guard test (chosen)** | No dependency, nothing to configure, and the prefix is visible in the file. The test is what makes it safe; without it a typo'd prefix would ship. Gives no version-aware ApiExplorer grouping, which nothing needs while there is one version. |
| `Asp.Versioning.Mvc` + `.ApiExplorer` | Version-aware ApiExplorer groups, `400` on an unknown version, a deprecation model. Two packages, `api/v{version:apiVersion}` templates everywhere, and a second concept to learn, to decide between one and two versions. Revisit if a v2 ever has to run beside v1. |
| `FallbackPolicy` for secure-by-default | One line, and `[AllowAnonymous]` still wins. But it is invisible at the route and hard to assert per endpoint; the convention does the same thing where a reader and a test can both see it. |
| A blanket `MapControllers().RequireAuthorization()` | Simplest to write, and wrong: requirements compose, so internal routes become unreachable. |
| Default lifetime validation only | Free, and leaves "≤ 2 minutes" unenforced — the rule that makes a captured token nearly worthless. |
| `ProblemDetails` built per controller | No shared mapper to learn, and the status for a code drifts between routes within a release. |

## Consequences

- A new route is protected unless it says otherwise, and `ApiRouteConventionTests` fails on an action that says nothing at all. It also pins the non-controller endpoint set to `/health`, `/alive` and `/openapi/{documentName}.json`, so a future minimal-API endpoint cannot slip past the controller-only convention.
- **Every code in `ErrorCodes` must have a status in `ApiProblemDetails`.** `ErrorCodeMapTests` enumerates the constants by reflection and fails on one that has none, because the fallback (400) would otherwise ship a status the contract never promised. `server.error` deliberately covers the whole 5xx family — a caller can do nothing differently for a 502 than for a 500.
- Codes for statuses that do not exist yet are added deliberately as their routes land: `square.unavailable` → 503 (5.2), a 429 code and `Retry-After` for the rate-limited forms (2.12 / 1.8), and a missing-`If-Match` code for CMS writes (2.8).
- Any change to a request or response shape fails `OpenApiContractTests` until the snapshot is regenerated in the same commit and the diff reviewed. That is the point, and it will be felt on every content prompt.
- **Deferred document work, to be done with the first real content route (2.4) rather than speculatively now:** tags come from controller class names, so a rename churns the snapshot and route-family tags would be steadier; there are no `operationId`s, so a generated client's method names follow paths; and the contract's headers (`Idempotency-Key`, `Idempotent-Replayed`, `ETag`, `If-Match`) are not in the document, so a removed `ETag` would not fail the snapshot.
- `AllowedHosts` is `*`, which is only safe because the gateway is the sole ingress (ADR 0001). If that ever stops being true, this is one of the places that has to change.
- `PingRequestedServiceModel.CorrelationId` is a `Guid` and serializes hyphenated, while the `correlationId` problem extension is the 32-hex W3C form. Both name the same concept in two spellings. The route is deleted in 1.12, which removes the inconsistency; any **new** ServiceModel carrying a correlation id uses the 32-hex form.
- 1.8 owes the gateway: mirrored `InternalTokenDefaults`, and `nbf`, `exp`, `iss`, `aud`, `token_use` and `sub` on every token it signs. Without all of them the API rejects every gateway token, so 1.8's contract test must assert the full set.
- Nothing here depends on Identity, so 1.9 adds the credential store without revisiting any of it. The roles are already the claim the policies read.
